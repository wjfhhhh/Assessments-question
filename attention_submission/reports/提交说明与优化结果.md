# 定点 Attention 项目提交说明与优化结果

提交者：wjfhhhh。整理与复测日期：2026-10-12。

## 1. 提交范围

本项目实现固定规模 `S=8、d=4` 的 Attention RTL 原型，输入一个 Q 向量与八组 K/V，输出四个 8 位有符号整数。基础功能按新版题目进行原始点积、最大值搜索、减最大值指数计算、加权累加和归一化。保留四种实现，分别对应基础版、A 因果 Mask、AB 优化版与进一步并行点积版。

基础设计的算法、位宽、状态机、接口与验证方法见 [六页设计报告](基础设计报告.pdf)及其 [Markdown 源文档](基础设计报告.md)。该报告保留较早的基础版实验记录；本文件中的复测、同条件综合与源码校验对应本次上传的正式 RTL。进阶 E/G 的独立调研见 [E_G调研报告](E_G调研报告.md)。

## 2. 数据流与数值规则

每个 Score 为四项 8 位有符号乘积的和。所有输入装载完成后，依次计算 Score、合法最大值、指数权重、分母 L 与四路 ACC，再输出 `round(ACC/L)`。

```text
Q/K/V 输入缓冲
    → 四维点积 → Score 缓冲与最大值
    → exp(Score − x_max) 查表 → 权重缓冲
    → L 与四路 ACC 累加
    → 带符号舍入除法 → 四个输出
```

权重保留四位二进制小数，使用整数编码表示实际值的 16 倍。指数查表采用最近值量化，差值 0、−1、−2、−3 对应编码 16、6、2、1，差值不大于 −4 对应零。L 与 ACC 使用相同缩放比例，因此归一化时直接用原始整数相除。最终半整数向远离零方向舍入。

| 数据 | 正式实现位宽 |
|---|---|
| Q、K、V、O | 8 位有符号 |
| 单项点积乘积 | 16 位有符号 |
| Score、差值 | 18 位有符号 |
| 指数权重编码 | 5 位无符号 |
| L | 8 位无符号 |
| 四路 ACC | 各 15 位有符号 |

四个最大乘积相加可达到 65536，需要 18 位有符号表示。并行点积版的加法树先扩展至 17 位得到两项和，再扩展至 18 位得到四项和；相加前显式符号扩展。

## 3. 接口与状态控制

基础状态顺序为：

```text
IDLE → LOAD_Q → LOAD_KV → DOT → MAX → EXP → UPDATE → NORM → OUTPUT → FINISH → IDLE
```

AB 与并行点积版将最大值搜索融入 DOT，取消独立 MAX 阶段。基础版和 A 版保持独立 MAX。

- `start` 仅在 IDLE 检查；忙碌时的 start 脉冲不排队。
- 解除复位且处于 LOAD_Q/LOAD_KV 时，`data_ready=1`；对应阶段的 valid 与 ready 同时为高的上升沿才接收数据。
- 四个 Q 分量与三十二对 K/V 分量收齐后才进入计算阶段。暂停输入不推进接收计数器。
- Q/K/V 数组在计算前完整覆盖，无需逐项复位清零。每次接受新 start 时清零 L 和四路 ACC。
- 输出阶段连续发送四个分量；FINISH 给出 done，随后回到 IDLE，支持任务之间不复位。

## 4. A 与 B 的实现

**A：因果 Mask。** 新增 Mask 开关和查询位置，并在接受 start 时锁存。只允许 `j <= query_index` 的 Key 参与最大值搜索，被屏蔽项权重强制为零。这样合法最大值至少产生编码 16，避免未来高分使合法权重全部量化为零。位置零至七、配置锁存和未来数据扰动均有独立测试。

**AB：并行累加与同步最大值。** 将四个 V 分量的乘法和 ACC 更新展开为四路，使每个 Key 的加权累加从四拍变为一拍，UPDATE 由 32 拍降到 8 拍。L 每个 Key 只更新一次。串行点积每完成一个完整 Score 就同步比较最大值，取消八拍 MAX 扫描。比较使用包含第四项乘积的完整结果，避免非阻塞赋值读取旧累加值；第一项合法 Score 直接初始化最大值，兼容全负分数。

**并行点积版。** 在 AB 基础上，用四路乘法和两层加法树同拍得到完整四维点积，DOT 从 32 拍降为 8 拍，每拍保存一个 Score。输入装载与最终归一化安排沿用原接口，没有实现 Online Softmax。

## 5. 提交包独立复测

重新从整理后的 `tests/` 目录实际生成向量、编译并运行，使用 Icarus Verilog 13.0。每个版本的正式 RTL 与 `demo/rtl/` 对应文件一致，结果中的源码 SHA-256 已核对。

| 版本 | 不同任务案例数 | Score 检查数 | 权重检查数 | 输出分量检查数 | 仿真退出码 |
|---|---:|---:|---:|---:|---:|
| 基础 | 1218 | 9744 | 9744 | 4872 | 0 |
| A | 1065 | 8520 | 8520 | 4260 | 0 |
| AB | 1071 | 8568 | 8568 | 4284 | 0 |
| 并行点积 | 1076 | 8608 | 8608 | 4304 | 0 |

所有案例通过。AB 与并行点积版还以 FAST_RESTART 模式重复同一组案例，检查快速连续任务；两遍不能计为两倍不同输入。各版另包含 2,074,793 个除法输入检查；进阶自检还遍历 130,561 个整数差值，核对指数表。

覆盖包括随机/极值输入、全负 Score、重复最大值、第四项影响最大值、最后合法项最大、Mask 开关和全部查询位置、未来数据扰动、输入停顿、忙碌 start、复位中断和无复位连续任务。除最终输出外，检查中间 Score、权重、L、ACC 与协议时序。

原始复测证据为 `tests/*/results/validation.json`、`simulation.log`，进阶目录另有 `coverage.json` 与 `fast_restart.log`。参考模型使用无溢出的 Python 整数，遵循相同的量化和舍入规则，通过数学求和计算预期结果，避免照搬逐拍状态机。

## 6. 现场演示与周期

四个现场 TB 每次只读取一组完整输入，不计算或读取预期答案。入口自动打印真实 RTL 的中间值与最终结果，换 HEX 后重新运行即可。

| 版本 | 无停顿 start→done | 最后 K/V 接收→done |
|---|---:|---:|
| 基础 | 125 拍 | 89 拍 |
| A | 125 拍 | 89 拍 |
| AB | 93 拍 | 57 拍 |
| 并行点积 | 69 拍 | 33 拍 |

AB 相对 A 减少 32 拍，约 25.6%；并行点积相对 AB 再减少 24 拍，约 25.8%；相对基础版共减少 56 拍，约 44.8%。输入暂停会延长 start→done，收齐输入后的固定计算周期不变。

`evidence/demo/delivery.log` 保留四版连续切换后再回到基础版的实测记录；`evidence/demo/status.json` 记录完成状态。当前演示默认输出均为 `[1,3,-1,6]`，但基础版与进阶版的默认输入不同。波形数据库位于 `evidence/demo_waves/`。

本轮还从整理后的提交目录重新创建工程并运行四个入口，记录在 `evidence/demo/submission_demo.log`。四个版本全部完成，输出与上表周期一致，随包提供的四个 WDB 已更新为该轮运行结果。

## 8. 工具问题与验证边界

本机存在两套 Vivado 路径。四版入口已修复工具与库搜索环境，避免展开阶段找不到仿真内核。项目运行不依赖提交包内携带工具 DLL。综合重跑发现本机在中文工作目录中可能异常，本次改用英文工作目录后四套综合报告全部生成。

本机 Vivado 在结束退出时仍出现访问异常，进程退出码为 −1073741819；报告生成完成与进程正常退出分别记录，不用 PASS 或文件存在掩盖工具异常。Icarus 四套自检则均正常退出。

E/G 完成资料调研及推导，未实现替代指数、参数化大规模电路、Online Softmax 或 FlashAttention。当前项目没有上板、布局布线和功耗测量结果，也不声称已经通过主办方隐藏测试。后续可重点优化除法关键路径、指数精度和分块数据流。
