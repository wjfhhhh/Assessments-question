基础版本，时序采用学习文档里面的推荐，但是没有单独的 NEXT 状态，而是把“切换到下一组”的动作放进了各阶段末尾的计数器控制逻辑。基础耗时是125拍

进阶部分首先完成的是A mask，掩码机制，主要原理是在基础版的基础上更新了以下内容：
1.加了两条输出入mask_enable 开关、query_index 查询位置，这两个值在接受到了之后就会锁存到寄存器，防止跳变
2.查找最大值的时候只查询合法地址，
从
if (token_index == 0 || score_mem[token_index] > x_max)
    x_max <= score_mem[token_index];
变为
if (token_index == 0 ||
    (key_allowed && score_mem[token_index] > x_max))
    x_max <= score_mem[token_index];

其中wire key_allowed =
    !mask_enable_reg || (token_index <= query_index_reg);
3.EXP阶段，从
wire signed [17:0] delta = score_mem[token_index] - x_max;
变为
wire signed [17:0] delta =
    key_allowed ? (score_mem[token_index] - x_max) : 18'sd0;

wire [4:0] lut_weight;

wire [4:0] masked_weight =
    key_allowed ? lut_weight : 5'd0;

exp_lut u_exp_lut (
    .delta(delta),
    .weight_raw(lut_weight)
);
就是如果不合法，就把delta和weight都设为0

在这之后继续完成了B
B分别优化了三个步骤：
1.首先优化了并行计算weight和V
原来的逻辑如下
address = token_index × 4 + elem_index
wire signed [13:0] weighted_product =
    $signed({1'b0, weight_mem[token_index]}) * v_mem[address];
所以要四拍来处理一个weight*V
后面改成了
wire signed [13:0] weighted_product [0:3];
wire signed [14:0] weighted_product_ext [0:3];

genvar lane;
generate
    for (lane=0; lane<4; lane=lane+1) begin: parallel_lanes
        assign weighted_product[lane] =
            $signed({1'b0, weight_mem[token_index]})
            * v_mem[token_index*4+lane];

        assign weighted_product_ext[lane] =
            {weighted_product[lane][13], weighted_product[lane]};
    end
endgenerate
用generate组合展开并行四个weighted_product的计算

2.update阶段原本acc要4拍来更新：
if (elem_index == 0)
    l_raw <= l_raw + {3'd0, weight_mem[token_index]};

acc_raw[elem_index] <=
    acc_raw[elem_index] + weighted_product_ext;
现在改为4个累加器
UPDATE: begin
    // 每个 Key 的权重只计入分母一次。
    l_raw <= l_raw + {3'd0, weight_mem[token_index]};

    // 同一个时钟沿，更新四个不同的累加寄存器。
    for (update_lane=0; update_lane<4; update_lane=update_lane+1)
        acc_raw[update_lane] <=
            acc_raw[update_lane] + weighted_product_ext[update_lane];

    if (token_index == 7) begin
        elem_index <= 0;
        state <= NORM;
    end else
        token_index <= token_index + 1'b1;
end

3.然后继续更新了DOT阶段，
直接将max阶段删去，融入DOT阶段，每算完一个score就直接比大小

这三步之后整个模块93拍

最后更新的一个版本是把qv的点积，以及DOT的score都并行计算，

用wire signed [15:0] dot_product [0:3];

genvar dot_lane;
generate
    for (dot_lane=0; dot_lane<4; dot_lane=dot_lane+1) begin: dot_lanes
        assign dot_product[dot_lane] =
            q_mem[dot_lane] * k_mem[token_index*4+dot_lane];
    end
endgenerate
展开计算一个key的4个维度，然后加法采用加法数减少拍数
// 第一层：两个十六位乘积，先扩展到十七位再相加。
wire signed [16:0] dot_pair0 =
    $signed({dot_product[0][15], dot_product[0]})
    + $signed({dot_product[1][15], dot_product[1]});

wire signed [16:0] dot_pair1 =
    $signed({dot_product[2][15], dot_product[2]})
    + $signed({dot_product[3][15], dot_product[3]});

// 第二层：两个十七位部分和，先扩展到十八位再相加。
wire signed [17:0] dot_sum =
    $signed({dot_pair0[16], dot_pair0})
    + $signed({dot_pair1[16], dot_pair1});

都是组合逻辑
所以最后也直接保存score，不必等待四拍保存一次：DOT: begin
    // 当前完整点积参与最大值比较。
    if (key_allowed &&
        (token_index == 0 || dot_sum > x_max))
        x_max <= dot_sum;

    // 每拍保存一个完整 Score。
    score_mem[token_index] <= dot_sum;
    score_data <= dot_sum;
    score_index <= token_index;
    score_valid <= 1;

    // 下一拍处理下一个 Key。
    if (token_index == 7) begin
        token_index <= 0;
        state <= EXP;
    end else
        token_index <= token_index + 1'b1;
end
